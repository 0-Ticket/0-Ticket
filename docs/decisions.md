# 결정 목록

팀이 정한 도구와 방식이다. "확정"인 것만 코드에 들어간다.

## 상태

| 상태 | 뜻 |
|---|---|
| 확정 | 팀이 정했다. 코드에 쓴다 |
| 후보 | 유력하지만 팀이 아직 의논하지 않았다. 쓰려면 계획 이슈에서 확정한다 |
| 담당자가 정함 | 그 부분을 구현하는 담당자가 계획 이슈에서 정한다. 예시는 참고용이다 |
| 추후 | 지금은 만들지 않는다 |
| 폐기 | 쓰지 않기로 했다 |

## 쓰는 법

- 정할 것이 생기면 계획 이슈의 "어떻게"에 적는다. `/soc-plan`이 확정되지 않은 도구나 방식을 발견하면 안건으로 올린다.
- 사람이 정하면 이 문서의 해당 행을 "확정"으로 옮기고 맨 아래 "기록"에 한 줄을 남긴다. 상태는 사람만 정하고, 사람이 정한 것을 AI가 받아 적는 것은 괜찮다.
- 결정을 바꾸면 같은 ID의 내용을 고치고 기록에 남긴다. 번호는 다시 쓰지 않는다.
- 다른 문서에서 결정을 가리킬 때는 `PostgreSQL(D-012)`처럼 설명을 먼저 쓰고 괄호에 ID를 쓴다. ID만 쓰지 않는다.

## 담당자가 정함

그 단계를 구현하는 담당자가 계획 이슈에서 정한다. 예시는 이전 논의에서 나온 안이며 그대로 따를 필요는 없다.

| ID | 정할 것 | 예시 | 담당 단계 |
|---|---|---|---|
| D-025 | L1 판정 결과 조건 | 확신도 임계값(설정, 예: 0.8) 이상이면 종결 또는 L2 승격, 미만이거나 형식 오류·호출 실패면 보류. 사람에게 넘기지 않음 | L1 |
| D-026 | Ticket 출처 구분 | L1 승격 / L3 승격 / 시나리오 세 가지 | L1, L2, L3 |
| D-027 | Incident 분류 방법 | L2 에이전트가 열린 Incident 목록을 보고 새로 만들지 기존에 붙일지 판단 / IP 같은 엔티티 기준 규칙 | L2 |
| D-028 | L2 재분석 기준 | 새 엔티티가 늘거나 반려됐을 때만, 자동 재분석은 최대 5회, 반려 2회면 사람 처리 | L2 |
| D-029 | L3 위협 시나리오 입력 | 보안 뉴스(RSS, CISA KEV)를 코드로 수집하고 에이전트에는 웹 접근을 주지 않음 | L3 |
| D-030 | L3 실행 방식 | 수동 명령 실행, 주기 실행은 설정으로 켬 | L3 |
| D-031 | 임베딩 모델 | bge-m3 로컬 실행 | 벡터 DB를 처음 쓰는 단계 |

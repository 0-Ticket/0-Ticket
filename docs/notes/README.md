# 개발 기록

이슈 하나를 끝낼 때마다 기록 하나를 남긴다. 계획(`docs/plans/`)이 "무엇을 하기로 했나"라면 기록은 "실제로 해 보니 어땠나"다. 다음에 같은 곳을 고치는 사람과 AI가 계획 전에 먼저 읽는다.

## 쓰는 법

- 이름: `<이슈번호>-<짧은설명>.md`. 같은 이슈의 계획 파일과 이름을 같게 한다.
- 형식: [`_template.md`](_template.md)
- 개발하면서 바로 쓴다. 특히 "다음 사람이 알아야 할 것"은 알게 된 그때 적는다.
- `/soc-done`이 마무리하고, 같은 내용을 PR 본문에도 요약한다.
- 코드와 PR에서 바로 보이는 것은 적지 않는다. 거기서 안 보이는 이유와 함정을 적는다.
- 비밀 값, 내부 주소, 실제 로그 내용은 적지 않는다. 확인 결과는 건수만 적는다.

## 찾는 법

```bash
grep -l "src/soc/l2" docs/notes/*.md docs/plans/*.md   # 코드 위치로
grep -il "incident" docs/notes/*.md                     # 낱말로
ls docs/notes | grep -E '^[0-9]' | sort -rn             # 이슈 번호가 큰 것(최근)부터
```

## 고칠 때

- 지난 기록은 고쳐 쓰지 않는다. 오타와 깨진 링크만 예외다.
- 이전 기록의 내용이 바뀌었으면 새 기록의 `supersedes`에 이전 파일 이름을 적는다.
- 기록에서 모두가 따라야 할 규칙이 나오면 팀이 의논해 `docs/decisions.md`나 `AGENTS.md`로 올린다.

# 화면을 pen.dev 디자인 14개 화면으로 교체

## 한 일

- 대시보드, 7개 목록·탭, 6개 상세 패널을 Pen 디자인의 검은 사이드바, 카드, 차트, 필터 칩,
  상태·위험도 배지, 필드표 모양으로 교체했다. 백엔드·API 클라이언트·생성 타입은 바꾸지 않았다.
- 대시보드 04번은 `ticket_status.escalated`를 쓰고, 전체 Ticket 수는 위험도 카드에 보존했다.
  분석 결과 Incident 목록·집계 새로고침·시간대 안내도 유지했다.
- 필터 칩은 같은 값을 다시 누르면 해제된다. 이전/다음 이동은 URL에 cursor 이력을 담고,
  필터를 바꾸면 이력·cursor·선택한 상세를 초기화한다. 전체 페이지 수는 합성하지 않는다.
- 상세의 객체를 필드표로 펼치고 원본 JSON으로 전환한다. 키·값·보고서·제안은 React 텍스트로만
  표시한다. 원본 Alert·Ticket·Incident·Hunt 이동과 실행 요약, 비활성 승인·반려를 유지했다.
- 확정한 폰트 4종을 로컬 번들로 불러오고 제공된 로고를 사용한다. 관리자 텍스트와 설정 버튼은
  계획대로 임시 표시이며 설정을 눌러도 요청이나 이동이 없다.

## 계획과 달라진 점

목표·범위·계약 변경은 없다. 다음은 구현하면서 정한 파일 분리와 표시 방식이다.

- 기존 페이지·조회 로직은 `App.tsx`에 유지했다. 새 공통 컴포넌트는 `filter-chips.tsx`,
  `json-viewer.tsx`, `icons.tsx`로 나누고 JSON 펼치기는 `json.ts`에 뒀다.
- URL의 반복 `trail` 인자에 지나온 cursor를 저장한다. 이력 없는 기존 cursor 링크는
  방문 시작 지점을 2 페이지로 표시하고 이전 버튼으로 첫 목록에 돌아간다. 실제 전체 페이지
  번호를 API에서 추론하지 않는다. 새로고침 뒤에도 이력이 있는 URL은 이전 페이지를 복원한다.
- 로고는 원본 비율을 보존한 112×139px PNG이며 디자인의 56×78px 상자 안에 `object-fit: contain`으로
  표시한다. 112×156px로 강제 변형하지 않았다.
- 정규화 도넛은 디자인처럼 성공·실패·대기 전체를 표시한다. 기존 성공률은 별도 문구로 보존하고
  성공/실패 기준임을 명시했다. 위험도 0과 API에 정의된 상태 이름은 기존 의미를 유지한다.

## 다음 사람이 알아야 할 것

- 디자인 원본 `0-Ticket.pen`은 커밋하지 않는다. 담당자가 보관한다. 이번 MCP는 VS Code 확장에
  열린 문서를 읽었다. 디자인 수치·SVG는 MCP와 HTML/CSS 내보내기로 확인했으며 내보낸 파일도
  커밋하지 않았다. 앞 세션의 아이콘 추출 실패는 SVG 속성 앞 줄바꿈을 처리해 해결했다.
- 디자인 폭은 960px(사이드바 224 + 본문 736)이다. 사이드바는 224px 고정이고 본문은 늘어난다.
  좁은 본문은 카드·칩을 줄바꿈하고 표 안에서 가로 스크롤한다.
- Incident 견본의 상태와 Risk Sum 표기는 실제 값과 달라 기존 상태 이름과 위험도를 쓴다.
  제목이 같은 Incident가 여러 개 있으므로 페이지 테스트는 고유 ID로 구분해야 한다.
- 보안 테스트는 상세 영역에 생긴 HTML 요소를 검사한다. 앱 전체의 정상 로고 이미지를 금지하지 않는다.
- 설정·관리자 표시는 D-020 전까지 인증·권한과 무관하다. 승인·반려, 로그인, SIEM 설정 동작은 없다.
- 사람이 최종 디자인·기능을 확인하고 PR 전·후 스크린샷을 첨부해야 한다. GitHub 쓰기는 하지 않았다.
- Vite의 기존 단일 청크 크기 경고가 남는다(JS 약 735 kB, gzip 약 221 kB).
  기본 pytest의 기존 FakeSshServer 종료 시 pending-task 경고 3건도 남으며 종료 코드는 0이다.

## 확인 방법

- 이전 세션: 손으로 만든 `tests/fixtures/frontend/json_viewer.json`과 새 테스트를 먼저 추가했다.
  구현 전 JSON 모듈 누락·신규 동작 실패를 확인했다. 정규화 전체 건수 테스트도 실패 확인 후 구현했다.
- `pnpm --dir frontend lint`: ESLint·Prettier 통과.
- `pnpm --dir frontend test`: 20건 통과. 기존 5개 시나리오를 유지하고 필터 해제, 출처·상태·위험도,
  이전/다음·cursor URL 복원·이력 초기화, 설정 무동작, JSON 양쪽 보기의 텍스트 표시를 검증했다.
  성공한 Alert/Event, Incident 보고서·대응 제안, Case 원본 이동, Hunt 실행 요약·기법도 검증했다.
  최종 검사 첫 실행은 기존 외부 문자열 테스트가 5초 제한을 넘겼다. 코드·제한을 바꾸지 않고
  전체를 다시 실행해 20건 모두 통과했다(11.35초).
- `pnpm --dir frontend build`: TypeScript·Vite 통과.
- `pnpm --dir frontend contracts:check`: 생성 타입 28개 일치.
- `uv run ruff format --check .`: 297개 파일 통과. `uv run ruff check .`: 통과.
- `uv run pytest`: 1,310건 통과, 기존 마커 설정에 따라 418건 제외(47.26초). 테스트 설정 변경 없음.
- 별도의 임시 로컬 PostgreSQL 16에 기존 마이그레이션과 `dev-seed-ui` 합성 시드를 적용했다.
  실제 FastAPI → Vite 프록시로 6종 목록과 상세 31건이 정상 응답함을 확인했다. 앱에 mock을 연결하지 않았다.
- Chrome에서 대시보드, Alert/Event·Ticket·Incident·Case·승인 대기·Hunting 목록과 6종 상세를 확인했다.
  대시보드·정규화 카드·상세 필드표를 스크린샷으로 확인하고, JSON 전환, Ticket → 원본 Hunt,
  Hunt 실행 요약과 승격 Ticket 링크, Incident 보고서·제안·비활성 승인/반려, Case 원본 링크를 확인했다.
  브라우저 확장 연결이 없어 기본 앱 제어로 확인했다. 사람의 최종 시각 검수는 별도다.

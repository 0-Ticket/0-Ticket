# 한도보다 큰 SIEM 히트가 0건으로 숨지 않게 하고, 인용은 `agl_`로만 하기로 했다

## 한 일

- `query_siem`이 히트 하나가 결과 한도(`max_tool_result_chars`)보다 커도 0건으로 돌려주지 않는다. 문자열 값은 모델에게 가는 직렬화 길이(양쪽 따옴표와 `…` 포함)가 300자 이하가 되게 자르고, 목록은 10개까지만 남긴다. 한 히트가 몫(`(한도 − 빈 본문) ÷ min(히트 수, 3) − 1`)을 넘으면 뒤에서 빼기 전에 줄이고, 그래도 안 맞으면 `{"siem_ref", "fields": {}, "fields_omitted": true}`만 보인다.
- 줄인 필드는 히트의 `truncated_fields`에 경로만 적는다(값은 없다). 줄이거나 `fields_omitted`로 바꾼 히트가 있으면 최상위 `truncated`가 `true`다. `omitted`는 지금처럼 한도 때문에 빠진 히트 수다.
- 인용은 인용-B다. `siem_ref`는 근거 ID가 아니고 `evidence_id` 계약은 그대로다(`format_error` 거부 유지). 원본 문서를 찾는 방법과 한계는 `docs/architecture.md` "SIEM 결과 되짚기"에 적었다. 결정은 D-058이다.
- `registry.py`에 `dumped_len(value)`(모델에게 가는 직렬화 길이)를 더하고 `_shorten`을 `shorten_record`로 이름만 공개했다. `_fits`도 `dumped_len`을 쓴다. 동작은 같다.

## 계획과 달라진 점

- **`test_query_with_no_room_for_one_hit_returns_zero_hits`의 기대값은 바뀌지 않았다.** 계획은 `chars=300`의 새 기대값을 실측해서 고치기로 했는데, 실측해 보니 300자는 "빈 본문(197자) + `siem_ref`만 있는 히트(116자) = 313자"보다 작아서 지금도 0건이다. 그래서 같은 이름의 테스트는 그대로 두고 이유를 주석으로 적었다. 한도 320자일 때의 새 동작(`siem_ref`만 있는 히트 1건, `omitted 39`)은 새 테스트 `test_query_with_room_only_for_a_siem_ref_shows_that_one_hit`가 확인한다.
- **기대값을 바꾼 기존 테스트는 하나다.** `test_query_web_access_builds_the_query_and_shapes_hits`: 긴 `url.query`를 자른 값의 길이 `== 301`을 `dumped_len(값) <= FIELD_MAX_CHARS`(표시 포함)와 `…`로 끝남으로 바꿨다. 계획에 적은 대로다. 지우거나 건너뛴 테스트는 없다.
- **목록 5,000개 테스트는 샘플 파일이 아니라 테스트 코드에서 응답을 만든다.** 샘플 파일은 목록 원소 12개짜리(`search_oversized_hit_wide.json`)만 두었다. 계획의 "손으로 만든 작은 샘플"을 지키려는 선택이다.
- **`_cap`은 글자 수가 300을 넘는 문자열을 직렬화하지 않고 바로 자른다.** 글자 수가 300을 넘으면 따옴표 2자를 더해 항상 한도를 넘기 때문이다. 응답이 최대 5MB여도 긴 값을 통째로 직렬화하지 않는다. 계획에 없던 작은 최적화다.
- **몫 계산에서 쉼표 한 자를 뺐다**(`- 1`). 히트 사이 쉼표가 몫 합계에 들어가지 않게 하려는 것이다.
- **안전망을 `siem_ref`만 있는 히트 한 건으로 한 번 더 시도한다.** 계획 4번("`siem_ref`조차 안 들어가면 `hits: []`")의 앞 단계다. 뒤에서 빼기로 다 빠졌으면 첫 히트의 `siem_ref`만 있는 히트가 들어가는지 본다.

- **몫 값을 4에서 3으로 바꿨다**(사람이 정함, 2026-11-16, 계획 "바뀐 점"에도 적음). 이유는 아래 "몫을 3으로 한 이유"다. 새 커밋으로 남겼다.
## 다음 사람이 알아야 할 것

### 실측값과 몫 값을 3으로 한 이유

모두 `uv run`으로 레포 밖 스크립트에서 돌린 값이다. `max_tool_result_chars`는 L1 6,000, L2·L3 8,000(`config/default.toml`).

- 빈 본문(`call_id`와 머리 칸, `hits: []`, `truncated: true`, `omitted`): 195~197자.
- 히트 하나의 직렬화 길이(`_cap` 뒤): 본문 재현 샘플 2,542자(줄인 경로 7개), 필드 10개·목록 12개 샘플 4,769자(15개), `search_large.json` 첫 히트 775자, 작은 히트 248자, 1,895자짜리 중간 히트(필드 4개가 280자)가 있다. 본문 재현은 `_cap`만으로 L1 6,000자 안에 든다.
- 한 히트의 몫(`HIT_SHARE_MAX = 3`): 히트 3건 이상이면 L1 1,934자, L2·L3 2,600자. 히트가 하나면 한도 전체다. (처음 계획값 4는 L1 1,450자, L2·L3 1,950자였다.)
- `search_large.json` 40건, `limit=100`, 한도별 보이는 히트:

  | 한도 | 보이는 히트 |
  |---|---|
  | 200~300 | 0건 (`omitted 40`) |
  | 320~400 | `siem_ref`만 1건 |
  | 500 | `siem_ref`만 2건 |
  | 1,000 | `siem_ref`만 6건 |
  | 3,000 | 줄이지 않은 히트 3건 (이전 코드와 같다. 몫 4에서는 줄인 히트 4건이었다) |

- 필드 10개·목록 12개 히트 1건(`wide`): 300자에서 0건, 350~1,500자에서 `siem_ref`만, 3,000자에서 줄여서 보임, 6,000자에서 줄이지 않고(`truncated false`, 4,965자) 보임. 몫이 한도 전체라서 줄이는 단계에 안 들어간다.
- 몫 값 민감도, 앞에 큰 히트(필드 10개·목록 12개) 1건과 작은 히트 8건:

  | 몫 값 | L1 6,000 | L2 8,000 |
  |---|---|---|
  | 1 | 5건 (뒤 4건 빠짐) | 9건 |
  | 2 | 9건, 큰 히트 2,818자로 줄임 | 9건, 3,868자 |
  | **3 (채택)** | 9건, 큰 히트 1,928자로 줄임 | 9건, 2,594자 |
  | 4 | 9건, 큰 히트는 `siem_ref`만(`fields_omitted`) | 9건, 1,928자 |
  | 5 | 9건, `siem_ref`만 | 9건, 1,559자 |
  | 6~8 | 9건, `siem_ref`만 | 9건, `siem_ref`만 |

- 보통 크기 히트 60건(`search_web_access.json` 복제), L1: 몫 2·3·4·6 모두 12건으로 같다. 보통 히트는 몫에 영향이 없다.
- 1,895자짜리 중간 히트 20건, L1: 몫 3은 몫(1,934자) 안이라 줄이지 않고 3건이 보인다(이전 코드와 같다). 몫 4는 4건이 각각 1,428자로 줄어 보였다.
- 몫을 3으로 한 이유: 처음에는 계획값 4로 구현했다. 실측해 보니 4에서는 큰따옴표·`<`로 채운 큰 히트(필드 10개·목록 12개)가 L1에서 `siem_ref`만 남았다. 이스케이프가 많은 값은 16자까지 줄여도 직렬화가 70자 안팎이라 몫 1,450자에 안 들어가기 때문이다. 사람이 몫을 3으로 정했다(2026-11-16). 3이면 같은 히트가 L1에서 1,928자로 줄어 보인다. 그 히트의 `source.ip`·시각·메서드·상태 코드는 그대로이고(`test_big_hit_first_does_not_hide_the_small_hits_behind_it`), 뒤의 작은 히트 8건도 모두 보인다. 몫 1만 뒤 4건을 잃고 2~8은 모두 작은 히트를 지킨다. 보통 크기 히트는 몫 2~6 어디서나 영향이 없다. 몫 2는 큰 히트를 더 길게 보이지만(2,818자) 보통 크기 히트를 줄이기 시작하는 한도가 L1 2,900자 안팎으로 올라간다. 값은 `HIT_SHARE_MAX` 하나로 바꾼다. **`shorten_record`의 최소 길이 문제(아래 기술 부채)가 고쳐지면 몫 값을 다시 볼 수 있다.** 그때는 4 이상으로 올려도 이스케이프가 많은 큰 히트가 `siem_ref`만 남지 않을 수 있다.

### 그 밖에

- **인용 방식과 되짚기.** 계약과 `src/soc/l1·l2·l3/`는 바꾸지 않았다. 되짚는 방법과 한계(뒤에서 빠진 히트의 `siem_ref`는 남지 않음, `fields_omitted` 히트의 내용은 Agent Log에도 없음)는 `docs/architecture.md`에 있다.
- **히트 모양이 늘었다.** `hits[]`에 `fields_omitted: true`가 있을 때만 생긴다. 모델 입력과 Agent Log tool 줄 `output`에 들어간다. `hits[]`를 읽는 코드는 레포 안에 없다.
- **#279와 맞춰야 할 점.** 반환 필드 목록(`TARGET_FIELDS`)은 바꾸지 않았다. `truncated_fields`와 `fields_omitted`에는 필드 경로 이름만 있고 값은 없다. 모델 입력 가림(D-048)은 SDK 입력 필터 한 곳이라 이 결과에도 그대로 적용된다.
- **작은 한도에서는 보이는 내용이 줄어든다.** 한도 1,000자(운영 설정에는 없다)에서 40건이면 `siem_ref`만 있는 히트 6건이 보이는데, 이전에는 줄이지 않은 히트 1건이 보였다. 운영 한도(6,000 이상)에서는 보통 히트가 몫 안에 들어 영향이 없다.
- **Windows에서 실패하는 테스트 둘은 이 이슈와 관계없다.** `tests/test_migrate.py::test_name_ending_in_newline_is_not_a_migration`(파일 이름에 줄바꿈 불가, 212 기록과 같음)과 `tests/test_tools_local_intel.py::test_tools_make_no_network_calls`(`ProactorEventLoop` 소켓 쌍이 네트워크 차단 가짜에 걸림, 이 변경을 빼도 같음). Linux CI에서는 통과해야 한다. Windows에서는 `PYTHONUTF8=1`이 있어야 `tests/test_api_ui.py`가 수집된다.

### 기술 부채 (후속 후보)

- **뒤에서 빠진(`omitted`) 히트의 `siem_ref`가 어디에도 남지 않는다.** 결과에 `omitted_refs` 같은 칸을 두거나 Agent Log에만 남기는 방법이 있다. 이번 범위 밖이다(계획 "범위 밖").
- **`count_siem`의 값 자르기는 글자 수(120자)다.** 큰따옴표·`<`로 채우면 직렬화 길이가 늘어 항목이 한도에서 밀려난다. 히트가 숨는 문제는 아니고 건수는 `other_count`에 남는다. `dumped_len`으로 같게 맞출 수 있다.
- **`truncated_fields`가 길다.** 값이 많이 잘린 히트는 경로 목록이 400자 넘게 몫을 차지한다. 경로를 줄이거나 한 칸에 묶으면 몫 안에 더 많은 값이 들어간다.
- **`shorten_record`의 최소 길이(16자)는 이스케이프가 많은 값에서 직렬화 70자까지 늘어난다.** 최소 길이를 직렬화 길이로 바꾸는 일은 `records` 도구에도 영향을 주므로 하지 않았다. 이 때문에 몫 4에서는 이스케이프가 많은 큰 히트가 L1에서 `siem_ref`만 남아 몫을 3으로 했다. 최소 길이가 직렬화 길이 기준으로 고쳐지면 몫 값을 다시 볼 수 있다(`HIT_SHARE_MAX`, 이 기록의 몫 표 참고).
- 인용-A(`siem_ref`를 근거 ID로 허용)는 필요해지면 계약 담당과 새 이슈에서 정한다. 그때 장부에 넣을 "보인 히트"는 `fields_omitted`가 아닌 히트로 하는 것을 권한다.

## 확인 방법

- `uv run ruff format --check .`: 395개 파일 통과, `uv run ruff check .`: 통과
- `PYTHONUTF8=1 uv run pytest`: 1,936건 통과, 2건 실패(위 Windows 전용 둘), 541건 제외(`db`·`llm`·`qdrant`·`elk` 마커). Windows에서 실행했다. 두 실패는 이 변경을 빼도(`git stash`) 같다는 것을 `test_tools_local_intel` 하나에 대해 확인했고, `test_migrate` 하나는 212 기록과 같은 원인이다.
- 먼저 쓴 테스트가 고치기 전 코드에서 실패했다: 새 테스트 14건 실패(본문 재현은 `total 1`에 `hits 0건`, 앞에 큰 히트가 있으면 9건 모두 0건).
- 새 테스트(`tests/test_tools_siem.py`, 네트워크 없음, `tests/fixtures/siem/search_oversized_*.json` 세 개): 본문 재현이 한도 안에서 보임, 값 하나가 `…` 포함 직렬화 길이 300 이하(큰따옴표·`<`·`>`·한글·이모지·제어 문자·역슬래시), 짧은 비ASCII는 안 잘림, 목록 5,000개가 10개로, 정확히 10개는 유지, 몫을 넘으면 줄이고 짧은 필드는 그대로, 못 줄이면 `siem_ref`만, 앞에 큰 히트 1건과 작은 히트 8건에서 작은 히트가 모두 보임, 줄인 결과를 `agl_`로 인용한 Verdict 통과와 Agent Log의 `siem_ref`가 모델에게 보인 값과 같음, 한도 320자에서 `siem_ref`만 있는 히트 1건.
- 기존 `test_citing_siem_ref_is_rejected`(`format_error`)와 `test_citing_alert_id_in_result_body_is_evidence_id_error`는 그대로 통과한다(인용-B에서 거부 유지).

# 수동 수집 명령 정리: 파이프가 떠 있는 상태에서 반복해서 안전하게 실행

## 목표

`uv run python -m soc.ingest`를 반복해서 실행해도 안전하게 만든다. 첫 실행 범위를 제한하고(`--since`, 기본 범위 설정), 겹쳐 실행되지 않게 막고, 끝에 요약(소스별 건수·구간·소요 시간·실패 이유)을 출력하고, 연결 실패 원인(인증·네트워크·인증서)을 구분한다. 이미 충족한 동작(증분 수집, 중복 건너뛰기, 소스 실패 격리, 종료 코드 1, 커밋된 건만 정규화에 보임)은 테스트로 고정한다.

## 방법

현재 동작은 `soc.ingest.run`(소스별 체크포인트에서 `gte`로 다시 읽기, 페이지 단위 `store.save_page` 트랜잭션, 소스 실패 격리)을 따른다. 아래만 더하거나 바꾼다.

**1. 시작 시각 규칙 (`run.py`, `__main__.py`, `config.py`)**

| 체크포인트 | `--since` | 시작 시각 |
|---|---|---|
| 없음 | 없음 | 지금 − `initial_lookback_seconds` |
| 없음 | 있음 | `--since` |
| 있음 | 없음 | 체크포인트 − `overlap_seconds` |
| 있음 | 있음 | `min(--since, 체크포인트 − overlap_seconds)` |

- 체크포인트가 있을 때 `--since`는 과거로 되돌리는 데만 쓰인다. 더 나중 시각을 줘도 구간이 비지 않는다.
- 첫 실행(체크포인트 없음)의 조회는 `time_field >= 시작 시각`이다. 지금처럼 `exists` 질의로 전체를 가져오는 경로는 없어진다. `elk.iter_pages`의 `start_ms`는 그대로 쓰되 `None`을 더 이상 넘기지 않는다(함수 시그니처는 바꾸지 않는다).
- `--since` 값: 상대 값(`30m`, `24h`, `7d`)과 시간대가 있는 ISO 8601만 받는다. 시간대 없는 시각·형식 오류·음수는 설정 오류(종료 코드 2)다. 미래 시각은 오류로 본다.
- `main()`은 인자를 받는다(`argparse`). 인자 없이 부르던 코드(`main()` 호출, 종료 코드)는 그대로 동작한다.

**2. 설정 (`config/default.toml`, `soc.ingest.config`)**

```toml
[ingest]
initial_lookback_seconds = 86400   # 체크포인트가 없고 --since가 없을 때 가져오는 범위(초)
overlap_seconds = 60               # 매 실행이 체크포인트보다 이만큼 앞에서 다시 읽는다(늦게 색인된 문서 완화)
```

- `Settings`에 두 필드를 기본값과 함께 더한다(기존에 `Settings`를 직접 만드는 코드가 깨지지 않게, `ca_cert_path`와 같은 방식). `read_settings`는 둘 다 0보다 큰 수(`overlap_seconds`는 0 이상)로 검사한다. 설정에 키가 없으면 기본값을 쓴다.
- 새 환경변수는 없다.

**3. 체크포인트 후퇴 방지 (`store.py`)**

- `_UPSERT_CHECKPOINT`가 기존 행의 `cursor->>'time_ms'`보다 클 때만 갱신한다. 갱신하지 않으면 `updated_at`도 그대로 둔다. 예전 빈 커서(`{}`)는 가장 낮은 값으로 본다.
- `save_page`의 반환 값·원본/격리 저장은 바꾸지 않는다. 호출자(`run.py`)와 테스트용 `tests/ingest/fake_elk.py`의 `FakeStore`가 같은 규칙을 따르도록 맞춘다. 다른 호출자는 개발 때 grep으로 확인한다.

**4. 동시 실행 방지 (`__main__.py`)**

- DB 연결 직후, ELK에 붙기 전에 `pg_try_advisory_lock(<수집 전용 키>)`를 잡는다. 키는 `soc.db.migrate`의 `LOCK_KEY`와 겹치지 않는 값이다. 세션 잠금이라 프로세스가 죽으면 연결이 끊기며 풀린다.
- 못 잡으면 "다른 수집이 실행 중이다" 한 줄(접속 정보 없음)을 stderr에 쓰고 종료 코드 3으로 끝난다. 원본·체크포인트·이력은 쓰지 않는다.
- 정규화가 저장 도중인 건을 읽지 않는 동작은 이미 충족한다(페이지가 한 트랜잭션으로 커밋되고 정규화는 커밋된 행만 본다). 코드는 바꾸지 않고 열린 트랜잭션을 둔 db 테스트로 고정한다.

**5. 요약 (`run.py`)**

- `SourceResult`에 `fetched`(가져온 hit 수)와 구간 시작·끝(epoch ms)을 더한다. 건너뜀은 `fetched − inserted − quarantined`로 계산한다. DB에는 저장하지 않는다(마이그레이션 없음).
- 구간은 `[시작 시각, 마지막으로 가져온 문서의 시각]`이다. 0건이면 시작만 적는다. 시각은 UTC ISO 8601이다.
- `format_results`는 소스마다 한 줄: `이름: 구간, 가져옴 n, 새로 저장 n, 건너뜀 n, 격리 n, 페이지 n, 소요 s초, 실패 <코드 또는 없음>`. 실패하면 이유 문구(원인별 안내)를 붙인다. 주소·키·계정 값은 쓰지 않는다. 마지막에 전체 소요 시간과 안내 줄을 출력한다.
  - 안내 줄(상태 조회 이슈 머지 전): "결과 확인: DB의 `ingest_runs`". 머지 후 명령 이름으로 바꾼다.
- 종료 코드: 0 모두 성공, 1 실패한 소스가 있거나 DB 오류, 2 설정·인자 오류, 3 다른 수집이 실행 중.

**6. 연결 실패 구분 (`errors.py`, `elk.py`)**

- `FAILURES`에 `tls`를 더한다. `elk._call`이 `httpx.ConnectError`의 원인 사슬에 `ssl.SSLCertVerificationError`가 있으면 `tls`로, 그 밖의 `httpx.HTTPError`는 지금처럼 `network`로 낸다(`tls`는 재시도하지 않는다). `ingest_run` 계약의 `outcome`은 정규식이라 마이그레이션이 필요 없다.
- 요약의 이유 문구: `auth`는 "ELK 인증 실패(키 환경변수 `<api_key_env 이름>` 확인)", `tls`는 "ELK 인증서 검증 실패(`ingest.ca_cert_path` 확인)", `network`는 "ELK에 연결하지 못함(네트워크·주소 확인)". 환경변수 이름과 설정 키 이름은 낼 수 있고 값은 낼 수 없다.

## 바꿀 곳

- `src/soc/ingest/__main__.py`: 인자(`--since`), 잠금, 시작 시각 계산 호출, 종료 코드 3, 요약 출력

- `src/soc/ingest/errors.py`, `src/soc/ingest/elk.py`: `tls` 실패 종류
- `config/default.toml`: 두 키 추가와 주석
- `tests/ingest/fake_elk.py`: `FakeStore` 체크포인트 규칙
- `tests/ingest/unit/test_run.py`, `test_config.py`, `test_elk.py`와 새 `test_since.py`·`test_lock`·`test_summary`, `tests/ingest/db/test_run_db.py`·`test_store_db.py`: 새 테스트와 출력 단언 수정. 샘플은 `tests/fixtures/`의 손 샘플과 `fake_elk.py`를 재사용하고 필요하면 `tests/fixtures/ingest/`에 더한다
- `.env.example`: 변경 없음(새 환경변수 없음)
- `docs/decisions.md`: D-057와 기록(이 계획 커밋에서 추가)
- `docs/plans/317-manual-ingest.md`, `docs/notes/317-manual-ingest.md`

## 다른 코드와 맞물리는 곳

- **`store.save_page`(공유 함수).** 체크포인트를 후퇴시키지 않는 조건이 더해진다. 시그니처·반환 값·원본/격리 저장은 그대로다. 호출자는 `run.py`와 이를 흉내 내는 `FakeStore`다. 기존 `tests/ingest/db/test_store_db.py`가 그대로 통과해야 하고, 체크포인트가 과거 값으로 덮어써지는 것을 기대한 테스트가 있으면 이 계획에 맞게 고친다.
- **`errors.FAILURES`.** 값이 하나 늘어난다(`tls`). 이를 쓰는 다른 곳이 있으면 개발 때 확인하고 notes에 적는다.
- **수집 출력 형식.** `format_results`의 줄 형식이 바뀐다. 이 출력을 파싱하는 코드는 없고 랩 cron은 로그로만 쓴다. `docs/notes/264-lab-cycle.md`의 절차는 고치지 않고(지난 기록) 새 notes에 바뀐 동작(기본 범위가 전체에서 최근 24시간으로)을 적는다.
- **종료 코드.** 기존 0·1·2는 의미가 그대로고 3이 늘어난다.
- 정규화, L1~L3, 계약, DB 테이블·마이그레이션, 도구 레지스트리는 바꾸지 않는다. `soc.pipeline`(#316)과는 코드가 닿지 않는다.

## 범위 밖

- Event 커서 필드를 `event.ingested`로 바꾸는 것(실제 ELK에서 필드를 확인한 뒤 별도 이슈. 랩 손 확인 때 존재 여부만 notes에 적는다)
- 소스 일부만 수집하는 옵션(`--only`)
- 요약 건수의 DB 저장, 마이그레이션, 상태 조회 명령(별도 이슈)
- 알럿↔이벤트 연결(`raw_links`) 채우기
- 수집을 파이프나 스케줄러에 넣는 것, 격리 보관·삭제, 실패 알림
- 정규화 failed 재시도

## 완료 기준

- [ ] 같은 명령을 연속으로 두 번 실행하면 두 번째에는 새로 저장한 건수가 0이고 중복이 없는 테스트가 있다(가짜 ES, 건너뜀은 0 이상)
- [ ] 체크포인트가 없을 때 `--since`와 기본 범위(`initial_lookback_seconds`)가 가져오는 구간을 제한하는 테스트가 있다. 시작 시각 규칙 표의 네 경우를 모두 확인한다
- [ ] 이미 수집한 구간을 `--since`로 다시 가져와도 중복이 저장되지 않고 체크포인트가 후퇴하지 않는 테스트가 있다(db)
- [ ] `--since`의 형식 오류·시간대 없는 시각·미래 시각이 종료 코드 2인 테스트가 있다
- [ ] 한 소스 실패 시 다른 소스는 수집되고, 성공한 소스의 체크포인트는 전진하고, 종료 코드가 0이 아닌 테스트가 있다
- [ ] 수집 명령이 동시에 두 개 실행되지 않고 두 번째는 종료 코드 3이며 아무것도 쓰지 않는 테스트가 있다(db, 잠금)
- [ ] 저장이 끝나지 않은(커밋 전) 건이 정규화 대상에 보이지 않는 테스트가 있다(db)
- [ ] 요약에 소스별 가져온 건수·새로 저장한 건수·건너뛴 건수·구간·소요 시간·실패 이유가 나오고, 키·주소·계정 값이 없는 테스트가 있다(표식 값을 환경변수에 넣고 출력에 없음을 단언)
- [ ] 인증 실패, 네트워크 실패, 인증서 실패가 서로 다른 실패 종류와 메시지로 나오는 테스트가 있다
- [ ] 겹침 구간(`overlap_seconds`)이 체크포인트보다 앞에서 읽고 중복이 저장되지 않는 테스트가 있다
- [ ] 손으로 확인(랩 ELK): 활성화 파이프가 떠 있는 상태에서 수집을 두 번 실행해, 두 번째가 새 건 0건이고 파이프가 끝까지 처리하는 것을 보았다. 건수·소요 시간을 `docs/notes/`에 적었다(사람이 숫자를 준다). 이때 Event 대상에 `event.ingested`가 있는지도 notes에 적는다
- [ ] 랩 계정·키가 코드, 테스트, 로그, notes, PR에 없다. 새 환경변수가 없으므로 `.env.example`은 그대로다
- [ ] 기존 수집 테스트(`tests/ingest/`)가 계획에 맞게 고친 것 외에는 그대로 통과한다
- [ ] `uv run ruff format --check .`, `uv run ruff check .`, `uv run pytest`, `uv run pytest -m "db or qdrant"` 통과
- [ ] `docs/plans/`에 확정 계획, `docs/notes/`에 개발 기록

## 토론으로 정한 것

- **체크포인트 전진 기준은 현행 유지(질문 1 A).** 소스가 중간에 실패해도 커밋된 페이지까지는 전진한다(D-050). 이슈의 "성공 지점은 성공한 소스만 앞으로 간다"는 "실패한 소스의 체크포인트는 실패 페이지 뒤로 가지 않는다"로 읽는다. 끝까지 성공할 때만 전진하게 하면 D-050을 바꾸고 실패 뒤 같은 구간을 통째로 다시 읽게 된다.
- **겹침 구간 60초(질문 2 A).** 증분이 `@timestamp` 기준이라 늦게 색인된 문서를 놓칠 수 있다(#232 기록이 로컬에서 재현). 겹침은 완화책이고 더 늦게 색인되는 문서는 못 막는다. 이 때문에 두 번째 실행의 "건너뜀"은 0이 아니다. 커서 필드 변경은 범위 밖이다.
- **`--since`는 체크포인트가 있어도 쓰고, 체크포인트는 후퇴하지 않는다(질문 3 B).** 공유 함수 `store.save_page`의 갱신 조건을 바꾼다. 여기에 시작 시각 규칙(질문 8)을 더해 `--since`가 체크포인트보다 나중이면 무시한다. 더 나중 시각이 덮어쓰면 사이 구간을 영영 못 가져오기 때문이다.
- **동시 실행은 advisory lock으로 즉시 포기, 종료 코드 3(질문 4 A).** 반복 시험 중 겹쳐 돌린 것을 바로 알리기 위해서다.
- **`--only` 옵션은 만들지 않는다(질문 5 A).** 설정의 소스 목록과 가짜 ES로 충분하다.
- **요약 건수는 DB에 남기지 않는다(질문 6 A).** 메모리에서 세어 출력만 한다. 상태 조회 이슈가 필요하면 그때 더한다.
- **#232는 읽었다(질문 7).** #232는 이슈가 아니라 #218을 닫은 머지된 PR이었다. 번호가 #191보다 크므로 읽었다.
- **결정 목록.** D-057를 확정으로 추가했다.
- 기본안으로 정한 것: 첫 실행 기본 범위 24시간(`initial_lookback_seconds = 86400`), `--since` 형식(상대 값·시간대 있는 ISO 8601), 구간 정의(시작 ~ 마지막으로 가져온 문서 시각, 0건이면 시작만), 안내 줄 임시 문구("결과 확인: DB의 `ingest_runs`"), 이유 문구에 환경변수 이름·설정 키 이름만 허용.

## 바뀐 점

# 확정 계획

이슈마다 사람과 AI가 토론해 확정한 계획을 하나씩 둔다. 개발은 이 파일을 기준으로 한다.

## 만드는 과정

1. 사람이 "작업 이슈" 템플릿으로 계획(무엇을 / 왜 / 어떻게 / 완료 기준)을 쓴다.
2. `/soc-plan <이슈번호>`: AI가 이슈와 관련 계획·기록·코드를 읽고 충돌, 오류, 빈칸을 질문으로 정리한다.
3. 사람이 답하고, 필요하면 AI와 다시 토론한다. 정해질 때까지 반복한다.
4. 사람이 "확정"이라고 하면 AI가 이 폴더에 계획 파일을 쓰고, 이슈에 붙일 댓글 초안을 낸다. 댓글은 사람이 단다.

## 파일

- 이름: `<이슈번호>-<짧은설명>.md`. 브랜치 이름의 뒷부분과 같게 한다.
- 형식: [`_template.md`](_template.md)
- 작업 브랜치의 첫 커밋으로 넣고, 코드·기록과 같은 PR로 머지한다.
- 토론 과정 전체는 남기지 않는다. 원래 이슈와 달라진 점과 그 이유만 "토론으로 정한 것"에 적는다.

## 개발 중에 계획이 바뀌면

- 사람이 정한 뒤 같은 파일의 "바뀐 점"에 날짜와 함께 한 줄을 추가한다. 위의 확정 내용은 고치지 않는다.
- 머지된 계획은 고치지 않는다. 다음 이슈의 계획에서 `supersedes`로 가리킨다.

# [UI] Incident 상세 화면을 디자인(.pen)과 일치하도록 보완

## 목표

`/incidents/:id`(#379·#380)가 `design/0-Ticket.pen`의 "Incident 상세" 7개 프레임과 같은 구성이 된다. 데이터 근거가 없는 요소(위험 경로, 반려 이력, 라운드 간 변화량)는 만들지 않는다. 화면용 응답과 `contracts/`는 바꾸지 않는다.

## 방법

### 분석 이력 탭

- `artifacts[]`를 라운드 타임라인으로 보인다(최신 라운드가 위). 라운드마다 제목(`분석 라운드 N`), 시각, `summary`, 판정(`verdict`)·심각도(`assessed_severity`)를 텍스트로 보인다.
- `Ticket +N`·`엔티티 +N`·`판정 변경 N` 칩과 반려/승인 이벤트 노드는 만들지 않는다(저장된 데이터가 없다, D-076). 필요한 필드는 아래 "범위 밖"에 적는다.
- 원본 JSON은 하단 접힘 "원본 보기(고급)"으로 옮긴다. 기존 `incident-round`의 `JsonViewer`를 쓴다.

### 개요 탭

- 2단: 왼쪽 사건 요약·영향·소속 Ticket, 오른쪽 핵심 엔티티·권고 조치. `impact`가 비면 "영향" 제목도 숨긴다.
- 핵심 엔티티 카드: 연결 Ticket 수(`entityRows`의 `tickets`) 상위 3개, 동률은 종류·값 순. `종류 · 값`을 텍스트로만 보인다.
- 소속 Ticket 행: 제목, `시각 · 근거 N개`, 판정 칩, 심각도 칩. UUID·복사·"Ticket 상세" 버튼은 없애고 행 전체를 눌러 Ticket 상세로 간다. 상위 5건과 "전체 보기".
- 권고 조치: 우선순위(높음·중간·낮음, D-072)와 카테고리(대응·탐지 룰)를 칩으로 보인다.

### 헤더, 엔티티·Ticket 탭

- 헤더: 제목과 승인/반려를 한 줄, 요약 숫자를 한 줄로 줄여 높이를 낮춘다. 탭 줄은 sticky(스크롤 조상의 `overflow`를 확인한다).
- 엔티티 탭: 값 열 너비를 확보하고(긴 값은 말줄임, `title` 툴팁에 텍스트) "복사" 버튼 줄바꿈을 없앤다. 작업 열 "그래프에서 보기"는 `?tab=graph&view=entity&node=<엔티티 키>`로 이동한다. 그래프가 그 노드를 선택해서 열고, 상위 60 밖이면 검색 일치처럼 위치를 건드리지 않고 더한다. 값은 텍스트로만 쓰고 주소에는 인코딩해서 둔다.
- Ticket 탭: 상세 보기 버튼을 행 우측으로 옮기고 시각을 한 줄로 보이며 페이지네이션을 확인한다.

### 관계 그래프

- **강조 방식 변경(계획 380 대체).** 노드를 hover하거나 선택하면 그 노드와 선으로 직접 이어진 노드·선은 그대로 두고 나머지는 투명도만 0.3으로 낮춘다. 나머지를 숨기거나 렌더에서 빼지 않는다. Ticket 보기·Entity 보기 공통이다.
  - 선택이 있으면 선택 노드 기준이고 hover는 임시로 덮어쓴다. 마우스가 노드를 벗어나면 선택 기준(선택이 없으면 원래대로)으로 돌아온다. 선택 해제(버튼·Esc)로도 돌아온다.
  - 검색 흐림과 겹치면 곱하지 않고 더 흐린 쪽 하나만 적용한다. 흐림은 CSS 클래스·투명도로만 한다.
  - hover·선택은 배치 계산에 들어가지 않는다(재배치 없음). 드래그·줌·검색·필터와 충돌하지 않는다. 터치에는 hover가 없고 선택만 강조한다.
  - 이로써 기존 "선택하면 직접 이웃만 남긴다"와 `neighbourhood`의 숨김 동작은 없앤다.
- **우측 패널.** 선택 노드의 "이 노드의 연결": 같은 Alert에서 `src`→`dst`로 이어진 직접 이웃을 종류·값 목록으로 보인다(단계 번호·역할 서사·"위험 경로" 없음). 연결 Ticket 수, 관련 Alert 수, 자산 중요도(있을 때만)를 보인다. Alert 제목·심각도는 응답에 없어 개수만 보인다(D-080).
- `PLAIN_LINES_BY_DEFAULT`는 `true`로 유지한다(사람이 화면을 보고 복잡하지 않다고 판단했다).

### 샘플 모드, 빈 상태, 로딩

- 개발 전용 화면 샘플 모드(`import.meta.env.DEV`일 때만 켜짐, 빌드 결과에는 들어가지 않는다)로 104개 엔티티 응답과 Ticket 0건 응답을 브라우저에서 본다. 기존 `tests/fixtures/frontend/incident_graph_entities.json`을 쓰고 새 서버 데이터는 만들지 않는다.
- 빈 상태("연결된 Ticket이 없습니다" + "분석 상태 새로고침")는 이미 있다. Incident 계약이 `ticket_ids` 1개 이상을 요구해 서버·`dev_seed`로는 Ticket 0건 Incident를 만들 수 없고, 샘플 모드와 테스트로만 재현한다고 기록에 적는다.
- 로딩은 페이지 전체 로딩 그대로다. 항목별 문구는 요청이 하나라 만들지 않는다.

### 테스트(먼저 쓴다)

- 기존 샘플(`incident_graph_entities.json`, `incident_page.json`)을 쓰고 손으로 만든 샘플을 필요한 만큼만 더한다. IP는 문서용 대역을 쓴다.
- 분석 이력: 라운드 순서·텍스트 표시·칩 없음·원본 접힘. 개요: 2단 구성, 핵심 엔티티 상위 3개와 동률 순서, 영향 비면 제목 없음, Ticket 행 구성(UUID 없음)과 행 클릭, 권고 칩. 엔티티 탭: "그래프에서 보기"가 `node` 주소를 만들고 상위 60 밖 엔티티도 선택된 채 열림, `__proto__` 값. 그래프: hover·선택 시 이웃 외 노드가 흐려지고(투명도 0.3) 제거되지 않음, hover가 선택을 덮어쓰고 벗어나면 복귀, 검색과 겹치면 더 흐린 쪽 하나, 드래그 후에도 동작, 패널의 직접 이웃 목록. 샘플 모드는 개발 환경에서만 켜짐.
- `neighbourhood`를 확인하던 `graph-model.test.ts`와 "선택 시 이웃만 남음"을 확인하던 `incident-graph.test.tsx`는 새 동작으로 다시 쓴다. 지우거나 건너뛰지 않는다.

- [ ] 개요가 2단이고 핵심 엔티티 카드(상위 3개)가 있으며, 영향이 비면 제목도 안 보인다

- [ ] 헤더가 한 줄 구성이고 탭 줄이 sticky다
- [ ] 엔티티 탭 값이 꺾이지 않고 "그래프에서 보기"가 `node` 주소로 그 엔티티를 선택해 연다
- [ ] Ticket 탭 시각이 한 줄이고 페이지네이션이 동작한다
- [ ] 우측 패널에 직접 연결 노드·연결 Ticket·관련 Alert·자산 중요도가 있고 "위험 경로"와 단계 번호는 없다
- [ ] 노드 hover·선택 시 직접 연결만 그대로이고 나머지는 흐려지며(숨김 없음) Ticket·Entity 보기 모두 적용되고 해제하면 복귀한다. 드래그·줌·검색·필터와 충돌하지 않는다
- [ ] 개발 전용 샘플 모드로 104개 엔티티와 빈 상태를 브라우저에서 확인할 수 있고 빌드 결과에는 없다
- [ ] `PLAIN_LINES_BY_DEFAULT = true`가 유지된다
- [ ] `contracts/`·화면용 응답이 바뀌지 않았고 D-081이 기록돼 있다
- [ ] `pnpm contracts:check`, `pnpm lint`, `pnpm test`, `pnpm build`와 `uv run ruff format --check .`, `uv run ruff check .`, `uv run pytest`가 통과한다

## 토론으로 정한 것

이슈 본문과 달라진 점:

- **위험 경로·연결 경로 N단계는 만들지 않는다(질문 1 B).** 근거가 되는 데이터가 없고 계획 379·380이 같은 이유로 뺐다. 대신 "이 노드의 연결"에 같은 Alert에서 `src`→`dst`로 이어진 직접 이웃을 보인다.
- **반려/승인 이벤트 노드와 라운드 칩은 만들지 않는다(질문 2 A, 3 A).** 반려는 `status`만 바꾸고 사유·시각을 저장하지 않으며(D-076) 라운드별 스냅샷도 없다. 필요한 필드는 "범위 밖"에 적었다.
- **"그래프에서 보기"는 주소에 `node`를 더한다(질문 4 A).** 계획 380의 "선택은 주소에 안 남긴다"를 이 한 가지에 한해 넓힌다.
- **104개 샘플과 빈 상태는 개발 전용 화면 샘플 모드로 본다(질문 5 A).** 공용 `ui_seed.json`을 바꾸지 않는다. 빈 상태는 계약상 서버 재현이 불가능하다.
- **항목별 로딩은 만들지 않는다(질문 6 A).**
- **`PLAIN_LINES_BY_DEFAULT`는 `true`를 유지한다(질문 7).** 사람이 화면을 보고 복잡하지 않다고 판단했다. 계획 380의 조건부 승인(`false`로 바꾸는 쪽)은 쓰지 않는다.
- **그래프 강조를 숨김에서 흐림으로 바꾼다(추가 요구).** hover·선택 모두 직접 연결만 그대로 두고 나머지는 투명도 0.3이다. 계획 380의 "선택하면 이웃만 남긴다"를 대체한다. 검색 흐림과 겹치면 더 흐린 쪽 하나만 적용한다(곱하지 않음, 사람이 확인).
- 결정 목록: D-081.

## 바뀐 점

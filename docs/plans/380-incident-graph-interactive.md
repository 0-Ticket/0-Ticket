# Incident 관계 그래프를 직접 조작하게 만들고 Entity 보기를 추가

## 목표

#379가 만든 전용 페이지의 "관계 그래프" 탭에서, 노드가 많아도 확대·축소, 이동, 노드 끌기, 필터·검색으로 쓸 수 있다. Ticket 보기에서는 Alert가 Ticket에 접혀 있다가 눌러서 펼쳐지고, 지금 "준비 중"인 Entity 보기(연결된 엔티티)가 동작한다. 화면용 API 응답은 바꾸지 않는다.

## 방법

### 데이터 (응답은 그대로, 화면이 구성한다)

- 노드와 선은 `IncidentDetail`의 `tickets[]`(`alert_ids`·`entities`), `alerts[]`(`id`·`time`·`entities`), `entity_criticality`로 새로 구성한다. 저장된 탐색 경로(`ticket_graphs`)는 그래프 선에 쓰지 않고 접힌 "분류 근거(고급)"에만 둔다.
- 엔티티 키는 `(type, value)`이고 정규화된 값끼리 정확히 비교한다(계획 379와 같음). 키는 `Map`이나 JSON 문자열로 잡고 일반 객체의 키로 쓰지 않는다. 값은 텍스트로만 그리고 링크·마크다운·HTML로 바꾸지 않는다. 접근성 라벨도 텍스트만 쓴다.
- 배치는 d3-force로 계산한다(D-079). 노드는 HTML, 선은 SVG로 직접 그린다. 확대·축소, 이동, 노드 끌기는 포인터·휠 이벤트로 직접 만든다. 휠 확대는 페이지 스크롤을 가로채지 않게 하고, 마우스 없이 쓰도록 +/−/초기화 버튼을 둔다.

### Ticket 보기

- 노드: Incident → Ticket → Alert. Alert는 처음에 Ticket 노드에 접혀 있고 Ticket을 누르면(또는 펼침 버튼) 펼쳐진다. 지금 데이터에서 Ticket당 Alert는 최대 1개(D-071)이지만 묶음 Ticket이 생기면 그대로 쓰이게 만든다.
- 엔티티 노드는 접힌 Ticket에는 그 Ticket의 엔티티가 직접 붙고, 펼치면 Alert의 엔티티가 Alert에 붙는다.
- Alert 노드는 제목·심각도 없이 시각·ID·엔티티 수로 표시한다.

### Entity 보기 ("연결된 엔티티")

- 노드는 Alert·Ticket의 엔티티다. 자산 등록과 상관없이 보이고, 자산이 있으면 중요도만 추가로 보인다(D-078).
- 같은 Alert에 함께 나온 엔티티끼리 잇는다. 같은 Alert 안에서 `src` role 엔티티에서 `dst` role 엔티티로 화살표를 그린다. 선에 설명 라벨을 붙이지 않는다. Alert가 없는 Ticket(Hunt)의 엔티티는 노드로만 보이고 서로 잇지 않는다.
- 범례: "화살표는 Alert에 기록된 출발→목적지 방향이며 공격 순서가 아님". 이름은 "연결된 엔티티"이고 공격 순서나 "위험 경로"로 읽히는 표현은 쓰지 않는다.
- 처음에는 연결 수 상위 60개만 보인다. 연결 수는 같은 Alert에 함께 나온 서로 다른 엔티티 수이고, 동률은 종류·값 순이다. 종류 필터를 켜면 그 종류만 다시 상위 60개를 보이고, 검색은 상위 60 밖의 일치 노드를 기존 노드 위치를 건드리지 않고 추가로 보인다.

### 조작

- 필터(종류)와 검색은 두 보기에서 노드를 숨기거나 강조한다.
- 노드를 선택하면 그래프 옆 상세 패널(지금의 검사 패널)이 열리고, 선택한 노드와 직접 이웃만 남기고 나머지는 숨긴다. "선택 해제" 버튼으로 돌아온다. 키보드로 노드를 고르고 선택할 수 있다(Tab, Enter·Space). 노드 이동은 포인터만 지원한다.
- 주소: `?tab=graph&view=entity`처럼 보기 전환(`view`)만 주소에 남기고 검색어·필터는 남기지 않는다. 노드 위치는 페이지 메모리에 두어 탭을 옮겼다 와도 유지하고 새로고침하면 초기화한다. 저장소에는 쓰지 않는다.

### 선 밀집 (조건부 사전 승인)

- 한 Alert의 엔티티를 모두 잇기 때문에 선이 많아 읽기 어려울 수 있다. 개발 중 엔티티 100개 이상 샘플 화면의 스크린샷을 사람이 보고 판단한다. 읽히지 않는다고 알려 오면, 기본 화면에는 `src`→`dst` 화살표만 그리고 같은 Alert에 함께 나온 나머지 연결은 노드를 선택했을 때만 보이게 바꾼다.
- 어느 쪽이든 배치 계산과 "연결 수" 순위는 같은 Alert 동시 출현 연결을 그대로 쓴다. 나머지 연결을 숨기면 화살표가 없는 엔티티가 선 없이 보이므로, 선택하면 연결이 나타난다는 안내를 범례에 둔다.
- 전환은 선 그리기 조건 한 곳에서 한다.

### 디자인 파일

- `design/0-Ticket.pen`에 새 Incident 상세 프레임을 추가하는 변경을 이 PR에 포함한다. 코드와 분리된 별도 커밋(`docs(design): …`)으로 둔다. 파일은 암호화돼 diff로 볼 수 없다. Entity 보기 프레임이 아직 없으면 사람이 개발 전에 알린다. 개발 시작 전에 pen MCP로 그래프·Entity 보기 프레임을 확인하고 다르면 알린다.

### 테스트(먼저 쓴다)

- `tests/fixtures/`에 손으로 만든 JSON 샘플: 엔티티 100개 이상, `src`/`dst` role이 섞인 Alert, role이 없는 엔티티, Alert 없는 Ticket, 키가 `__proto__`·`constructor`인 엔티티 값. IP는 문서용 대역을 쓴다.
- 프런트 테스트(jsdom): 노드·선 구성(Ticket 보기·Entity 보기), 화살표 데이터(`src`→`dst`만, 중복 합침), 상위 60 상한과 종류 필터·검색의 동작, Alert 접기·펼치기, 선택 시 직접 이웃만 남음과 선택 해제, 키보드 선택, `view` 주소 유지, 위치 기억(탭 이동 후), 엔티티 값이 텍스트로만 그려짐, 자산 중요도가 있을 때만 보임, 범례 문구. 좌표·시각 확인은 jsdom에서 하지 않고 스크린샷으로 사람이 본다.
- 기존 `incident-graph.test.tsx`는 새 동작에 맞게 옮긴다. 지우거나 건너뛰지 않는다.

## 토론으로 정한 것

이슈 본문과 달라진 점:

- **Alert 노드 필드(질문 2)는 응답을 바꾸지 않는다.** 시각·ID·엔티티 수로 표시한다. 담당 승인 없이 프런트만 바꾸기 위해서이고, 제목·심각도는 후속 이슈로 둔다.
- **그래프는 응답의 Ticket·Alert·엔티티로 새로 구성하고 저장된 탐색 경로 선은 그리지 않는다(질문 3).** 같은 엔티티 노드에 여러 Alert가 이어지면 공유가 이미 보이고, 두 종류의 선이 섞이면 읽기 어렵다.
- **선택하면 직접 이웃만 남기고 나머지는 숨긴다(질문 4).** 이슈 문구("그 노드의 연결만 보인다")대로이고 선택 해제 버튼을 둔다. 상세 패널은 그래프 옆 검사 패널이다.
- **상위 60개 규칙(질문 5).** 연결 수는 같은 Alert에 함께 나온 서로 다른 엔티티 수, 동률은 종류·값 순이다. 종류 필터를 켜면 그 종류만 다시 상위 60개이고 검색은 60 밖 일치 노드를 위치를 건드리지 않고 더한다.
- **주소와 위치 기억(질문 6).** `view`만 주소에 남기고 위치는 페이지 메모리에 둔다.
- **Alert 접기를 구현한다(질문 7).** 지금은 Ticket당 Alert가 최대 1개(D-071)라 효과가 작지만 묶음 Ticket에 대비한다.
- **Alert 없는 Ticket의 엔티티는 서로 잇지 않는다(질문 8).** 이슈에 없는 관계를 만들지 않는다.
- **d3-force는 D-079로 확정한다(질문 1).** 배치 계산만 쓰고 줌·이동·끌기는 직접 만든다.
- **화살표 범례** 문구는 사람이 정했다: "Alert에 기록된 출발→목적지 방향이며 공격 순서가 아님".
- **선 밀집은 조건부로 사전 승인했다.** 엔티티 100개 이상 샘플 화면의 스크린샷을 사람이 보고 읽히지 않는다고 알려 오면, 기본 화면에는 `src`→`dst` 화살표만 그리고 나머지 같은 Alert 연결은 노드를 선택했을 때만 보이게 한다(위 "선 밀집").
- **`design/0-Ticket.pen` 변경을 이 PR에 포함한다.** 사람이 새 Incident 상세 프레임 7개를 저장해 두고, 코드와 분리된 `docs(design): …` 커밋으로 올린다. Entity 보기 프레임이 아직 없으면 사람이 개발 전에 알린다. 이 변경은 별도 PR이 아니라 #380 PR에 들어간다.
- 결정 목록: D-079.

# 차단된 공격 시도도 L1에서 위협으로 판정해 L2로 승격

## 목표

WAF 등이 이미 막은 공격 시도도 L1이 `malicious`로 판정해 L2로 올라가게 한다. L1은 정오탐을 가르고, 공격이 막혔는지 뚫렸는지(영향도)는 L2가 가른다. 프롬프트만 고치고 Verdict 계약과 `decide()`(D-025)는 바꾸지 않는다.

## 방법

L1은 정오탐, L2는 정탐의 영향도, L3는 놓친 것을 다시 보는 헌팅이다. 이 경계를 지킨다.

- L1: 공격 시도의 흔적이 근거로 확인되면 차단 여부와 관계없이 `malicious`다. 정상 활동으로 설명되는 경우만 `benign`이다. 차단 여부를 알아내려고 추가로 조회하지 않는다. 트리아지하다가 이미 본 응답 코드나 WAF 필드가 있을 때만 `reason`에 사실로 적고, 못 봤으면 적지 않는다.
- L2: 정탐으로 올라온 건의 영향도를 `attempted`(차단돼 성공하지 못함), `succeeded`(성공), `inconclusive`(확인하지 못함)로 가른다. 차단된 시도를 `not_threat`으로 닫지 않는다. 확인하지 못했으면 `inconclusive`로 두고 `impact`는 빈 문자열, 이유는 `summary`에 한 줄 쓴다.
- `web.md`는 현재 L1 프롬프트에 합성되지 않는다(어떤 `AgentTask`도 `domains`를 넘기지 않는다). 효과는 `l1.md`가 낸다. `web.md`는 나중에 연결돼도 모순이 없게 고친다.
- 프롬프트 파일에는 금지 문구 검사(`FORBIDDEN_PHRASES`)가 걸려 있으므로 "대응을 실행", "지시를 무시" 같은 말은 부정문으로도 쓰지 않는다.

## 바꿀 곳

- `src/soc/agent/prompts/l1.md`: 위 L1 기준. 6행의 "공격 흔적이 근거로 확인될 때 위협"에 "차단 여부와 관계없이"와 이미 본 차단 여부를 `reason`에 적는 기준을 더한다.
- `src/soc/agent/prompts/domains/web.md`: 3행의 "응답 코드와 응답 크기로 실제로 성공했는지 따로 본다"를, 성공 여부는 위협 여부의 기준이 아니라 이미 본 경우 `reason`에 적을 사실이라는 문장으로 바꾼다. 4행의 스캔 구분 지침은 그대로 둔다.
- `src/soc/agent/prompts/l2.md`: 7행 영향 범위에 "공격이 차단됐는지 성공했는지를 응답 코드와 이후 요청으로 확인해 적고, 확인하지 못했으면 그렇다고 적는다"를 더한다.
- `src/soc/l2/prompts/l2_report.md`: 차단돼 성공하지 못한 시도는 `attempted`이고 `not_threat`이 아니라고 쓰고, 확인하지 못했으면 `inconclusive`로 두고 이유를 `summary`에 쓴다. 3행의 기존 규칙(확인하지 못한 impact와 cause는 빈 문자열)은 바꾸지 않는다.
- `tests/test_agent_prompts.py`: 합성한 L1 프롬프트(`domains` 없음, `domains=("web",)`)와 L2 합성 프롬프트에 새 기준이 들어가는 테스트, `l2_report.md` 문구 테스트, 금지 문구 검사 통과 확인을 더한다. 기존 테스트는 지우거나 건너뛰지 않는다.

## 다른 코드와 맞물리는 곳

- 계약, `decide()`, 설정 키, 테이블은 바꾸지 않는다.
- `l2_report.md`는 L2 담당이 쓰는 파일이라 이 계획에 적는다. 바꾸는 것은 문구뿐이고 출력 계약(`incident_analysis`)은 그대로다.
- 프롬프트 내용이 바뀌므로 `prompt_version`(합성 프롬프트의 해시)이 바뀐다. 이전 Agent Log와 비교할 때 달라 보이는 것은 정상이다(`docs/notes/210-llm-prompts.md`).
- 개발용 시드(`tests/fixtures/l1_e2e/dev_seed.json`)의 `task_prompt`는 별도 프롬프트라 바꾸지 않는다.

## 범위 밖

- `domains`를 L1에 연결하는 것(별도 이슈. Alert가 웹인지 판별할 기준이 필요하다).
- 페이로드 없는 단순 스캔의 판정 변경. 지금 판단을 유지한다. 랩 시험 결과를 보고 따로 정한다.
- 랩 nginx 로그가 HTTP Activity(4002)로 정규화되지 않는 문제(`docs/notes/264-lab-cycle.md` 발견한 문제 1).
- L1이 차단 여부를 조사하는 것. L1이 L2나 L3의 일을 하게 하는 문장은 어느 프롬프트에도 쓰지 않는다.
- L3 코드와 프롬프트 변경.

## 완료 기준

- [ ] `l2.md`에 차단·성공 확인과 미확인 표기가 있고, `l2_report.md`에 `attempted`·`inconclusive` 기준이 있다

- [ ] ELK 랩에서 WAF가 403으로 막은 공격(예: SQL 인젝션)으로 실제 모델을 돌려 Ticket이 `escalated`가 되고 L2 보고서의 `verdict`가 `not_threat`이 아닌 것을 확인해 PR에 적는다. `inconclusive`면 4002 정규화 문제 때문인지 이유를 같이 적는다. 랩 시나리오 실행은 사람이 한다
- [ ] 정상 요청에 가까운 알럿이 여전히 `benign`으로 판정되는지 같은 방법으로 확인해 PR에 적는다
- [ ] `uv run ruff format --check .`, `uv run ruff check .`, `uv run pytest`가 통과한다

## 토론으로 정한 것

이슈 본문과 달라진 점:

- **`web.md`는 L1에 합성되지 않는다.** 어떤 `AgentTask`도 `domains`를 넘기지 않아서다. 이슈의 "왜"(`web.md`가 막힌 시도를 `benign`으로 만든다)는 지금 코드에서는 `l1.md`와 모델 성향 탓이다. 그래서 `l1.md`가 단독으로 기준을 담고, `web.md`는 이슈대로 고치되 `domains` 연결은 별도 이슈로 뺐다.
- **`l2_report.md`를 범위에 넣었다.** L2 보고서의 `not_threat`은 Incident를 `dismissed`로 종결하므로(`src/soc/l2/analyze/store.py`), `l2.md`만 고치면 L2가 차단된 공격을 닫을 수 있다.
- **미확인 표기는 `inconclusive` + 빈 `impact`로 한다.** 이슈의 "그렇다고 적는다"를 `l2_report.md`의 기존 규칙과 맞추기 위해서다. 이유는 `summary`에 쓴다.
- **L1은 차단 여부를 조사하지 않는다.** 이미 본 사실만 `reason`에 적는다. 영향도는 L2의 일이고, L1의 `max_turns`와 입력 예산이 영향도 조사에 쓰이지 않게 하기 위해서다.
- **완료 기준에 L2 `verdict` 확인을 더했다.** 이슈의 목적이 L2에서 정보가 이어지는 것이기 때문이다.
- **단순 스캔은 이번에 바꾸지 않는다.** 막힌 시도를 모두 올리면 Ticket과 사람 검토 대기가 늘 수 있어서, 랩 시험 결과를 보고 따로 정한다.

`docs/decisions.md`와 `docs/architecture.md`는 바꾸지 않는다.

- 2026-11-11 · 사람이 나머지 리뷰 지적의 수정을 정함. `l1.md`는 흔적의 예를 들고 "거부된 로그인 한 건처럼 흔적이 뚜렷하지 않은 것"은 흔적으로 보지 않게 한다. `web.md`는 페이로드 모양이 "정상 이용으로 설명되지 않으면" 흔적으로 보게 하고 어긋나던 응답 코드 문구를 맞춘다. `l2.md` 영향 범위 줄은 "분석 작업"으로 한정한다. 테스트의 L2 프롬프트 경로는 `soc.l2.analyze.tasks.PROMPT_DIR`을 쓰고, 단어 부재 테스트는 뺐다.
- 2026-11-11 · 사람이 두 번째 리뷰 지적의 수정을 정함. `l1.md`의 흔적 예에서 "알려진 공격 도구나 패턴"을 뺀다(확정한 4-A, 페이로드 없는 단순 스캔은 이번에 바꾸지 않음과 어긋나서). `l2_investigate.md`·`l2.md`는 "응답 코드"를 "응답 코드나 성공·실패 기록"으로 일반화하고 조사 줄에 "해당하는 경우"를 붙인다. `l2_investigate.md`의 첫 규칙은 "확인한 사실과 확인하지 못한 점만"으로 맞춘다. `l2_report.md`에 `succeeded` 기준을 더하고 중복된 "impact는 빈 문자열"을 뺀다.

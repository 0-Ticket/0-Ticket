# 마무리: 검사 · 기록 · PR 초안

검사를 통과시키고 개발 기록을 마무리하고 PR 초안을 쓴다. push와 PR 생성은 사람이 한다.

## 절차

1. **검사.** 아래를 차례로 실행한다. 화면 코드가 있으면 그 폴더의 검사(타입 검사, 린트, 테스트, 빌드)도 실행한다.

   ```bash
   uv run ruff format .
   uv run ruff check .
   uv run pytest
   ```

   실패마다 원인을 한 줄로 설명하고 고친 뒤 다시 실행한다. 같은 실패를 3번 고쳐도 안 되면 멈추고 보고한다.

2. **완료 기준 확인.** 계획 파일의 "완료 기준"과 `AGENTS.md` "완료 기준"을 하나씩 확인한다. 실제 SIEM·실제 모델처럼 직접 확인하지 못한 항목은 "사람이 확인"으로 표시한다.

3. **기록 마무리.** `docs/notes/<파일>.md`를 끝낸다.
   - "한 일"은 이슈를 읽지 않은 사람도 이해하게 쓴다.
   - "다음 사람이 알아야 할 것"이 비어 있으면 정말 없는지 한 번 더 본다. 임시 처리, 하지 않은 것, 확인하지 못한 것은 여기에 적는다.

4. **커밋.** 로컬에 커밋한다. 메시지에 AI 표시를 넣지 않는다.

5. **PR 초안.** `.github/PULL_REQUEST_TEMPLATE.md` 형식으로 쓴다. 대상은 `main`이다.
   - 제목: `<type>(<scope>): <summary> (#<이슈번호>)`. squash 머지되면 이 제목이 `main`의 커밋 메시지가 된다
   - "한 일", "다음 사람이 알아야 할 것"은 기록 파일을 요약한다
   - 관련 이슈: 이슈마다 `Closes #<번호>`를 한 줄씩

## 출력

- 완료 기준 충족 여부 (항목별 ✅ / ❌ / 사람이 확인)
- 기록 파일 경로와 "다음 사람이 알아야 할 것" 요약
- PR 제목과 본문 초안 (복사해서 바로 쓸 수 있게 코드 블록으로)
- 사람이 실행할 명령: `git push -u origin <브랜치>`

## 하지 않을 것

- 테스트를 지우거나 건너뛰게 만들어 통과시키지 않는다. 실제 모델·DB 테스트를 마커로 나누는 것은 예외다.
- 린트 규칙을 끄거나 예외 주석으로 넘기지 않는다. 꼭 필요하면 PR 초안에 이유를 적는다.
- `git push`, `gh pr create` 등 GitHub에 쓰는 명령을 실행하지 않는다.

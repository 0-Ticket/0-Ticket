# 결정 검토

`docs/decisions.md`의 항목 하나(D-xxx)를 비교 검토해 사람이 결정할 수 있게 정리한다. 결정은 사람이 한다.

## 입력

- 결정 ID (예: `D-007`). 관련 이슈 번호가 있으면 함께.

## 절차

1. `docs/decisions.md`에서 해당 항목의 후보, 관련 박스, 메모를 확인한다.
2. `docs/architecture.md`에서 관련 박스의 절(특히 "완료 조건")과 "구현 순서"를, `docs/product-spec.md`에서 관련 시나리오를 읽는다.
3. 이 결정에 영향을 주는 다른 결정이 있는지 확인한다. 예: D-003은 D-002에 따라 달라진다.
4. 후보마다 공식 문서나 저장소를 확인해 아래 기준으로 비교한다. 확인한 출처 링크를 남긴다.
   - 관련 박스의 완료 조건을 충족하는가
   - 설치와 실행 난이도 (로컬 노트북에서 돌아가는가, 필요한 메모리)
   - 라이선스와 비용
   - Python 3.12 + uv에서 쓸 수 있는가
   - 나중에 다른 후보로 바꾸기 쉬운가
5. 필요하면 가장 작은 실험을 제안한다. 실험 코드는 만들지 않고 방법만 적는다.

## 출력 (아래 형식 그대로)

```
D-xxx <항목>

후보 비교
| 기준 | 후보 A | 후보 B |
|---|---|---|

추천: <후보> — <이유 두세 줄>
추천하지 않는 이유: <다른 후보마다 한 줄>
영향: <바뀌는 박스, 다른 결정, data-contracts 영향>
확인한 출처: <링크 목록>
남은 질문: <사람이 정해야 할 것>
```

## 하지 않을 것

- `docs/decisions.md`의 상태를 직접 "확정"으로 바꾸지 않는다. 사람이 결정한 뒤 요청하면 상태와 "결정 기록"을 고친다.
- 후보를 설치하거나 실행하지 않는다.
- 공식 문서로 확인하지 못한 내용은 "미확인"이라고 적는다.
